# Architecture

## What The Application Is

The project is a client-side React application. The browser downloads the application once, and React changes the visible page when the URL changes. There is no custom backend or database in this repository.

The project uses:

- **React** to create reusable user-interface components.
- **TypeScript** to describe data and catch mistakes before the app runs.
- **Vite** to run the development server and create production builds.
- **React Router** to connect URL paths to page components.
- **CSS** for all layout, colors, typography, and responsive behavior.

## Folder Structure

```text
.
├── docs/                 # Project documentation
├── public/               # Files served as-is by Vite
├── src/
│   ├── assets/           # Imported image and asset files
│   ├── App.tsx           # Routes, shared header, pages, and page data
│   ├── App.css           # Component and page styles
│   ├── index.css         # Global browser and document styles
│   └── main.tsx          # React application entry point
├── index.html            # The HTML document containing the root element
├── package.json          # Dependencies and npm commands
├── package-lock.json     # Exact dependency versions installed by npm
├── tsconfig*.json        # TypeScript settings
├── vite.config.ts        # Vite configuration
└── eslint.config.js      # ESLint rules
```

The `dist/` folder is generated by `npm run build`. Do not edit it by hand. It is output, not source code.

## Application Entry Point

`src/main.tsx` finds the element with the id `root` in `index.html` and renders the `App` component inside it. `StrictMode` helps identify unsafe React patterns during development.

The flow is:

```text
index.html
    ↓
src/main.tsx
    ↓
src/App.tsx
    ↓
React Router chooses a page
    ↓
Page components use CSS from App.css and index.css
```

## Main React Pieces

### `SiteHeader`

`SiteHeader` is shared by every page. It contains:

- the navigation links
- the active route styling
- the site brand link back to Home

If you add or remove a main navigation item, update the `navItems` array near the top of `src/App.tsx`.

### `PageTemplate`

`PageTemplate` prevents the informational pages from repeating the same header and layout markup. It receives:

- `title`: the page heading
- `intro`: the short introduction under the heading
- `sections`: an array of section headings and paragraphs

This is an example of a reusable component: change the template once and all pages using it can benefit.

### `HomePage`

`HomePage` contains the visual landing page, mission section, educational cards, and responsibility sections. The cards are generated from the `featureCards` array instead of being written four separate times.

### Page Components

These components supply the content for their routes:

- `AboutConcussionsPage`
- `AboutCTEsPage`
- `AthleteCornerPage`
- `SymptomsPage`
- `AboutUsPage`
- `ResponsibilitiesForCoachesPage`
- `MorePage`

## Routing

Routes are defined at the bottom of `src/App.tsx`:

```tsx
<Route path="/" element={<HomePage />} />
<Route path="/about-ctes" element={<AboutCTEsPage />} />
```

Use React Router's `Link` for internal links. Do not use a normal HTML link for an internal route unless you intentionally want a full page reload.

- `Link` changes pages inside the React app.
- `NavLink` does the same and can tell you whether its route is active.
- `Route` maps a URL path to a React component.
- `Routes` chooses the matching route.
- `BrowserRouter` enables browser-based routing.

## Data Flow

The home page stores card data in `featureCards`. Each card contains a title, description, image URL, and destination route. React maps over that array and creates one linked card per item.

To add another card:

1. Add an object to `featureCards`.
2. Create a destination page component if needed.
3. Add a matching `Route`.
4. Confirm the card link opens the intended page.

## External Images

The current cards and hero sections use remote Unsplash image URLs. That means images require an internet connection and could change or become unavailable. For a more reliable production site, download approved images into `src/assets/` or `public/`, check their usage rights, and update the image references.
